## Architecture Decision

### AD-1: temporal_claim as infer relation, not Fact enum variant

**Context**: FR-1 requires classifying evidence as state/rate/intervention_sensitive. Two options:

1. **Add TemporalClaim variant to Fact enum** — breaks semver contract (knowledge.rs is STABLE, used by zz-notation and inferense)
2. **Define temporal_claim as a built-in relation** — register `temporal_claim/2` and `temporal_claim_adequate/3` as reserved relations in KnowledgeBase, no type changes needed

**Decision**: Option 2 — built-in relation. The existing `RelationSymbol` + `Fact` structs already support arbitrary predicates. Adding `temporal_claim(btc_price, state)` is just a new `Fact` with a reserved `RelationId`. No breaking changes.

**Consequences**:
- infer-core semver stays compatible
- zz-notation and inferense unaffected
- Downstream consumers (reasoning-apps) query temporal_claim like any other relation
- Parser needs a reserved-relation check so `temporal_claim` args are validated (Type must be `state|rate|intervention_sensitive`)

**Implementation**:
```
reasoning-universe/infer/
├── crates/infer-core/src/knowledge.rs  — add TEMPORAL_CLAIM_ID constant + validation
├── crates/infer-core/src/solver.rs     — no changes (generic resolution works)
├── crates/infer-parser/src/parser.rs   — add reserved-relation arg validation
├── examples/49_temporal_claims.infer   — new example
└── crates/infer-tests/tests/temporal_claims.rs — tests
```

### AD-2: CSC card as ctop DSL node type, not comment header

**Context**: FR-2 originally proposed CSC metadata as a comment block. But ctop is actually a **Compact Token-Oriented Protocol** — a schema-aware DSL/AST/binary format. A comment header is throwaway; a proper ctop node is queryable and roundtrips.

**Decision**: Define `csc_card{}` as a ctop node type:

```
csc_card{
  stronger_source: "full component tree (247 nodes)"
  weaker_rendering: "pruned context (31 nodes)"
  supported_use: "single-component edit"
  unsupported_use: "cross-component refactoring, dependency analysis"
  reopen_trigger: "imports, types, or callers not in context"
}
```

**Consequences**:
- CSC metadata survives encode/decode roundtrip
- Can be queried programmatically (`ctop parse | grep csc_card`)
- LLMs receiving ctop-encoded context see structured CSC metadata, not informal comments
- Requires ctop schema extension (new node type registration)

**Implementation**:
```
infra-eco/ctop/
├── src/dsl/          — add csc_card node type to schema
├── src/validate.rs   — validate CSC well-formedness (WF-1 from FPF spec)
├── examples/         — add csc_card example
└── tests/            — roundtrip tests
```

### AD-3: Cross-component contract — TemporalClaimType enum

**Context**: Both infer and reasoning-apps will need to speak the same temporal claim vocabulary. Without a shared contract, `state` in infer might mean something different than `state` in reasoning-apps.

**Decision**: Define the canonical type set in infer-core as string constants (not a separate crate):

```rust
// infer-core/src/knowledge.rs
pub const TEMPORAL_STATE: &str = "state";
pub const TEMPORAL_RATE: &str = "rate";
pub const TEMPORAL_INTERVENTION: &str = "intervention_sensitive";
```

Reasoning-apps (Python) validates against these same strings when bridging:
```python
TEMPORAL_TYPES = {"state", "rate", "intervention_sensitive"}
```

**Consequences**:
- No new crate or dependency
- String-based contract — simple but requires manual sync
- If vocabulary grows, consider a shared proto/schema later
